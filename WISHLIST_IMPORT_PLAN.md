# План: импорт списка желаемого из Steam (2026-07-24)

> Как сделать кнопку «Импортировать из Steam» в разделе «Желаемое».
> **Код не написан** — это проектный документ. Все факты об API ниже
> **проверены живыми запросами**, а не взяты из головы: часть «очевидных»
> подходов оказалась нерабочей (см. §2).

---

## 1. Что уже проверено и работает

### 1.1 Список желаемого — один запрос, без API-ключа ✅
```
GET https://api.steampowered.com/IWishlistService/GetWishlist/v1/?steamid=<steamid64>
```
Ответ: `{"response":{"items":[{"appid":1620,"priority":0,"date_added":1431499859}, …]}}`

Проверено на реальных аккаунтах: **6987** и **41** позиция. Ключ Web API **не
нужен**. Работает только для **открытого** профиля (приватный отдаёт пустой
`items` — это надо честно показать пользователю, см. §5).

### 1.2 SteamID64 определяется автоматически ✅
Не надо просить пользователя вводить ID. Локальная установка Steam уже знает:
```
<SteamPath>\config\loginusers.vdf
  "76561199873062942" { "AccountName" "…" "PersonaName" "…" "MostRecent" "1" }
```
Проверено на этой машине — файл есть, ID извлекается, флаг `MostRecent` даёт
последний вошедший аккаунт. `SteamPath` берётся из реестра
`HKCU\Software\Valve\Steam` — **этот код в проекте уже есть**
(`game_manager.py:1066-1079`, `SteamScanner`), надо переиспользовать, а не
писать заново.

### 1.3 Приоритет и дата из Steam ✅
`priority`: `0` = без ручной сортировки, `1..N` = позиция в ранжированном
списке. `date_added` — unix-время, ложится прямо в наш `added_date`.

## 2. Что НЕ работает (проверено — не тратить на это время)

| Подход | Результат проверки |
|---|---|
| `store.steampowered.com/wishlist/profiles/<id>/wishlistdata/?p=0` (старый эндпоинт со всеми деталями пачкой по 100) | **Мёртв** — отдаёт не-JSON. Раньше это был самый удобный путь; в статьях в интернете он до сих пор советуется. |
| `appdetails?appids=1620,50650` (пакетный запрос деталей) | **HTTP 400.** Steam больше не отдаёт несколько игр за раз. |
| `appdetails` без `cc` для региональных игр | `success=false` — см. баг с 007 First Light. Обязательно передавать регион + фоллбек. |

**Следствие:** детали (название, обложка) можно получить **только по одной игре
за запрос**. Это главное ограничение, вокруг которого строится дизайн.

Что удалось смягчить: `appdetails?appids=<id>&filters=basic` работает и отдаёт
`name` + `header_image` — payload заметно меньше полного. Для карточки этого
достаточно.

## 3. Ключевая проблема: стоимость деталей

Наш `WishlistItem` требует название и обложку → **1 HTTP-запрос на игру**.
У Steam лимит примерно **200 запросов / 5 минут** на IP (при превышении —
временный бан, а у нас уже есть анти-бан меры в `CoverAPIManager`, ронять их
нельзя). Для списка из 300 игр наивный импорт = ~8 минут долбёжки и риск бана.

### Решение: двухфазный импорт с ленивой догрузкой

**Фаза 1 — мгновенная (1 запрос).** Тянем список appid'ов и создаём записи
`WishlistItem` сразу, с пустыми `title`/`header_image_url` и флагом
`needs_details=True`. Пользователь моментально видит «Импортировано 247 игр».

**Фаза 2 — фоновая догрузка.** Фоновая задача обходит записи с
`needs_details`, по одной, **с троттлингом ~1.2 сек между запросами**
(≈50 запросов/мин — вдвое ниже лимита), обновляет карточку и сохраняет.
Прогресс — ненавязчивой строкой в шапке раздела («Загружаю детали: 37/247»).
Прерывается при закрытии приложения, продолжается при следующем запуске
(флаг в JSON переживает перезапуск).

Плюсы: импорт ощущается мгновенным, лимиты не нарушаются, прерывание
безопасно. Карточка без деталей рисуется по заглушке (градиент + appid),
код для этого в `_build_wishlist_card` уже есть (ветка без `header_image_url`).

недоступные в основном регионе — без фоллбека они импортируются безымянными.

## 5. Крайние случаи (обязательно обработать)

| Ситуация | Поведение |
|---|---|
| Профиль приватный | `items` пуст, но HTTP 200 → **не** молчать «импортировано 0», а сказать: «Список желаемого скрыт настройками приватности профиля» + как открыть. |
| Steam не установлен | ID не найден → сразу форма ручного ввода. |
| Введён vanity-URL (`/id/nickname`) | `ResolveVanityURL` требует Web API-ключ, которого у нас нет. Проще: попросить именно SteamID64 и дать ссылку на steamid.io, ИЛИ распарсить `g_steamID` со страницы профиля (хрупко — как фоллбек). |
| Огромный список (5000+) | Предупредить: «Детали будут догружаться ~2 часа в фоне» и предложить импортировать только первые N. |
| Повторный импорт | Идемпотентен: существующие app_id пропускаются, приоритеты пользователя не затираются. |
| Игра удалена из Steam | `appdetails` → `success=false` в обоих регионах → пометить и не долбить повторно каждый запуск. |

## 6. Порядок работ

1. `steam_get_wishlist` + `find_local_steamid64` + юнит-тест на реальном
   публичном аккаунте (эндпоинт уже проверен — тест закрепит).
2. `needs_details` в модели + `import_from_steam` (идемпотентность).
3. UI: кнопка + диалог + мгновенный результат фазы 1.
4. Фаза 2: фоновая догрузка с троттлингом, прогресс, продолжение после
   перезапуска.
5. Крайние случаи из §5, в первую очередь приватный профиль.

**Оценка:** пункты 1-3 — основная ценность, ~половина работы. Пункт 4 —
вторая половина (фоновая задача + прогресс + возобновление).
